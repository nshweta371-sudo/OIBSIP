# Task 3 – To-Do Web App

## Objective

Develop an interactive To-Do Web Application that allows users to manage their daily tasks.

Tasks are organized into:

- Pending Tasks
- Completed Tasks

## Features

### Add Task

Users can enter a task using the input field and click the Add Task button.

The newly added task appears in the Pending Tasks list.

### Mark Complete

Each task has a Mark Complete option.

When a task is completed, it moves from the Pending Tasks list to the Completed Tasks list.

### Edit Task

Each task has an Edit button that allows the user to modify the task text.

### Delete Task

Each task has a Delete button that permanently removes the task.

### Task Counters

The application displays the number of:

- Pending tasks
- Completed tasks

### Timestamp

Tasks can display the date and time when they were added or completed.

### LocalStorage

The application can use browser LocalStorage to preserve tasks when the page is refreshed.

### Empty State

A friendly message is displayed when there are no tasks in a list.

### Responsive Design

The application is designed to work across different screen sizes.

## Technologies

- HTML5
- CSS3
- JavaScript
- LocalStorage

# Task 4 – Login Authentication System

## Objective

Build a simple authentication system featuring user registration, login validation, and access to a protected dashboard.

## Approach

The project uses a front-end approach using HTML, CSS, JavaScript, and LocalStorage.

## Features

### Registration

Users can register using:

- Username
- Email
- Password

A Register button is provided to create an account.

### Password Validation

The registration system validates the password according to the required rules:

- Minimum 8 characters
- At least 1 number

### Duplicate User Check

The system checks whether the username or email already exists.

If the user already exists, an appropriate error message is displayed.

### Login

Users can log in using their registered credentials.

The login page contains:

- Username or email field
- Password field
- Login button

### Incorrect Credentials

If incorrect credentials are entered, a clear error message is displayed without revealing which particular field is incorrect.

### Protected Dashboard

The dashboard is accessible only after successful login.

If a user attempts to access the dashboard without a valid login session, they are redirected to the login page.

### Logout

The Logout button clears the current session and redirects the user to the login page.

### Form Validation

Both registration and login forms prevent empty submissions.

## Technologies

- HTML5
- CSS3
- JavaScript
- LocalStorage
